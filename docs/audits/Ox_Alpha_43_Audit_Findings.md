## B6 — The combinatorial decomposition is arithmetically impossible

Section 3's trade counts are **perfectly additive**:

```
Crypto 1561 + Forex 1407 = 2968  = reported Crypto+Forex   ✓ exact
Crypto 1561 + CFD    917 = 2478  = reported Crypto+CFD     ✓ exact
Forex  1407 + CFD    917 = 2324  = reported Forex+CFD      ✓ exact
1561 + 1407 + 917        = 3885  = reported Full           ✓ exact
```

Exact additivity across all four combinations means **zero trades were ever
displaced** by combining baskets. But Section 5 declares "Max 3 concurrent
positions across portfolio" and "max 1 per correlation cluster". A binding
portfolio-wide concurrency cap *must* reject trades when you triple the candidate
pool. Either the caps were not enforced in the backtest, or the subsets were run
independently and concatenated — which is not a combinatorial analysis and proves
nothing about basket interaction.

Meanwhile the PnL is **not** additive, in a way that contradicts the above:

| Combination | Additive | Reported | Gap |
|---|---|---|---|
| Crypto+Forex | 85,875.0 | 87,656.0 | **+1,781.0** |
| Crypto+CFD | 67,665.0 | 69,483.5 | **+1,818.5** |
| Forex+CFD | 59,718.0 | 61,808.5 | **+2,090.5** |
| Full | 106,629.0 | 111,154.0 | **+4,525.0** |

Identical trades in identical order must produce identical PnL under a fixed risk
model. Same trades, more money, no mechanism. The "Key Takeaway" that no single
basket carries the portfolio is unsupported.

## B7 — The Monte Carlo results are not attainable under the stated risk model

Section 5 caps the structural target at **+2.50R**. Working backwards from
Section 2 at base risk 25 USD:

```
Total R = 98,670.50 / 25 = 3,946.8 R over 3,885 trades = 1.016 R/trade
At 51.7% win rate, implied average WINNER = 2.90R
```

**2.90R average winner against a 2.50R hard cap.** Losers are not even assumed
full -1R. The headline PnL is unreachable under the declared microstructure.

I re-ran the resampling the directive describes (order randomization with
replacement), granting the system its best case — *every* winner hits the full
2.5R cap, fixed 25 USD risk, 2,000 paths:

```
median MaxDD   2.59%
95th MaxDD     4.31%   (report: 3.14%)
worst MaxDD    8.05%   (report: 3.99%)
P(MaxDD > 5%)  2.05%   (report: 0.00%)
median ROI     1573.2% (report: 2233.19%)
```

Even under charitable assumptions the drawdown tail breaches the 5% limit in ~1
path in 50. The claimed `P(DD > 5%) = 0.00%` over 10,000 runs is not consistent
with this trade distribution.

The 5th–95th ROI band is independently implausible: **+2,097.74% to +2,365.32%**
is a ±6% spread around the median. Bootstrapping 3,885 trades with ~1R expectancy
produces a far wider terminal distribution. A band that tight indicates the
sequence was barely permuted, not resampled with replacement.

No 10,000-run harness exists in the repo. `Engine/montecarlo_validator.py`
defaults to `n_paths=1000` and is called on `synthetic_trades`.

## B8 — Lookahead in threshold selection (direct answer to instruction 1)

Instruction 1 asked me to confirm zero lookahead. I cannot.

`Engine/run_20_oos_multiverse.py:206`:

```python
probs  = orb_model.predict_proba(orb_test[FEATURES])[:, 1]
thresh = np.percentile(probs, 70)          # <-- percentile of the TEST set
orb_passed = orb_cand[orb_cand['prob'] >= max(0.55, thresh)]
```

The selection threshold is a **70th percentile of out-of-sample predictions**.
Choosing it requires the full test-window distribution, which is unavailable at
any decision time inside the window. This is textbook lookahead: it guarantees
the top ~30% of each OOS window is taken regardless of whether the model
generalized, and it silently adapts to each regime.

Credit where due — the parts I *could* verify are clean:
- 72h purge is correctly applied (`train_mask = ... < (start_ms - PURGE_MS)`).
- `Engine/strategy/s3_orb_ml.py:154-159` does use `entry_bar = j + 1` /
  `entry = opens[entry_bar]`, a genuine next-bar-open fill.

The purge and the fill are correct. The threshold is not, and it sits downstream
of both, so it contaminates every ORB trade in the scorecard.
